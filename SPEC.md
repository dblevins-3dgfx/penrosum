# Penrosum: Specification

Status: an experimental prototype. This describes the game as currently implemented (`Game` in `src/Game.tsx`, the How to play and Top 10 dialogs in `src/HowToPlay.tsx` and `src/Scoreboard.tsx`, rules in `src/lib/rules.ts`, the top 10 in `src/lib/scores.ts`, how values are written in `src/lib/labels.ts`, board in `src/lib/board.ts` and `penrose-board.ts`, fitting it to the screen in `src/lib/view.ts`, saved choices in `src/lib/prefs.ts`). Rules not decided yet are listed under [Open questions](#5-open-questions), and each option is playable from the **How to play** dialog. Questions already decided are recorded under [Resolved questions](#8-resolved-questions).

## 1. Overview

A merging game on a Penrose tiling of kites and darts. Values climb a ladder of powers of 3, written as letters: **#** for 0, then **A** (1), **B** (3), **C** (9), **D** (27) and on up to **Z**. The player places the next value, dealt at random with a shape and shown in advance, on an empty tile of that shape. When that makes a group of three or more matching tiles, they merge into the tile just placed, which climbs the ladder: three As make a B, three Bs make a C, and a big enough group can jump further (nine As make a C). A merge of exactly three leaves a # of rubble behind. Merges score points; the game ends when the board is full, and the best scores on each board size make a top 10. Making a Z wins outright. Each game starts with a few values already scattered on the board.

## 3. Board

- **Tiling.** `penrose-board.ts` is Penrogo's board generator, unchanged (only its patch generator is used): a patch of kites and darts made by subdividing a sun of five kites 7 times, so it is a correct Penrose tiling by construction (see Penrogo's spec, section 4).
- **Sizes.** Three board sizes, each a square playfield in board units (the kite's long edge is 60 units), with an exact tile count (`BOARD_SIZES`). The sides are the ones whose random boards hold that many tiles on average:

  | Size | Playfield | Tiles |
  |---|---|---|
  | Small | 360 x 360 | 50 |
  | Medium (default) | 485 x 485 | 100 |
  | Large | 660 x 660 | 200 |

- **Shape.** Every board is square, so it fits the screen the same way whichever way the screen is turned; rotating a phone mid-game just rescales the board.
- **Placement.** Every New Game cuts a different board from the patch (`boardFor`): the square is centered on a random point within 1,100 units of the patch's center (`MAX_OFFSET`; the patch covers about 1,740, so the square is always fully covered) and turned to a random angle, and keeps the tiles lying fully inside it (`makeBoard`). Penrose tilings have no preferred direction, so any angle looks natural. A placement is redrawn until the board holds exactly its size's tile count and is **in one piece**: every tile can be reached from every other through neighbors (`isConnected`), so no tile is stranded where it could never merge. About one placement in six has the exact count, so this takes a few tries (a few milliseconds). In the unlikely case that 500 tries (`MAX_TRIES`) find none, the one-piece board closest to the count is used.
- **Variety.** Boards differ in their mix of shapes as well as their layout: kites make up about 62% of a medium board on average, from about 56% to 67%. The kites mostly link into larger regions, while the darts sit in small clusters (at most five-dart stars), so darts are the scarcer, more scattered spots.
- **Adjacency.** Two tiles are neighbors when they share a full edge, so a tile has at most four neighbors. Tiles on the ragged edge of the board have fewer, but every tile has at least one. Shared edges are matched on the patch's own coordinates (`edgeKey`), so the matching is the same whatever the placement.

## 4. Rules

- **Values.** Every value is a power of 3, or 0: 0, 1, 3, 9, 27 ... up to 3 to the 25th. Each is written as a letter (`valueLabel` in `src/lib/labels.ts`): **#** for 0, then **A** for 1, **B** for 3, **C** for 9, **D** for 27 and so on to **Z** for 3 to the 25th (`TOP_VALUE`). Letters are used everywhere a value appears: on the tiles, in the Next chip, the hover preview, the stats and the status line ("Merged 3 tiles into B").
- **Start.** Each new game seeds the board: 10% of its tiles (`SEED_FRACTION`, rounded), picked at random, get a random value from the ones the deck deals, #, A, B or C (`SEED_VALUES`), each equally likely. Neighboring seeds never hold the same value, so no group exists before the first move; a picked tile whose neighbors already hold all four values is passed over for another. Seeded #s can't be played on and match only a placed #, so they act as obstacles; dealt #s can merge them (see **Merge**). Seeded tiles look the same as placed ones. Undo goes back as far as the seeded board.
- **Tiles** are either empty or hold a value. A tile can hold # (a seed, or a placed #), which can't be played on and matches only a placed #.
- **Next value.** Each move's value is drawn at random from the deck (`DECK`) before the move and shown in advance ("Next" in the panel). A draw is a wildcard, shown as ★, 5% of the time (`WILD_CHANCE`); otherwise it is a number (`NUMBERS`): # 10% of the time, A 63%, B 18% and C 9% (A, B and C at 7 : 2 : 1).
- **Wildcard.** A ★ is placed like a number and becomes whichever value does best there (`resolveWild`). It tries each value held by a neighbor, plays out the move with it (chain reactions included), and keeps the one that merges rather than not; among merges, the one leaving the highest value; then the one clearing the most tiles. If no neighbor's value would merge, it is placed as an A. So a wildcard can complete any group, including values higher than the deck ever deals (two Ds and a wildcard make an E). The status line says what it became ("Wild played as B."), and the hover preview shows the result before the move.
- **Shape.** Each value is dealt with a shape too (`dealShape`), a kite or a dart, on the board it will be played on. The chance of a kite is the kites' share of the empty tiles (`kiteChance`): with 30 empty kites and 10 empty darts, 75%. So the deal follows the board the player is making (and each board's own mix of shapes, see Board: **Variety**), the two shapes tend to run out together, and a shape with no empty tile is never dealt: once one shape's empty tiles are all filled, every value comes with the other.
- **A move** places the next value on an empty tile of its shape (`canPlaceDealt`). As a safeguard, if no empty tile of that shape were left, any empty tile would do (`shapeToPlace`); the deal above never lets that happen.
- **Group.** After placing, the group is the placed tile plus every matching tile connected to it through other matching tiles (tiles are connected when they share an edge). So a long chain of matching tiles collapses all at once, even when the placed tile is at its end. Matching tiles hold the same value; shape doesn't matter, so kites and darts match each other. Tiles with a different value never join the group, and the group never passes through them; #s join only a placed #.
- **Merge.** If the group has 3 or more tiles (`MIN_GROUP`), the placed tile takes the sum of their values **rounded down to a power of 3** (`mergeResult`, `floorPow3`), and the other tiles in the group become empty: they leave the board and can be played on again, so free space comes back after every merge. Three or four As make a B (3 or 4, rounded down to 3), five Bs make a C (15 to 9), and nine As make a C, so a big enough group can climb more than one rung; whatever doesn't make a full rung is lost. Shape never changes what a merge makes. Otherwise nothing else changes. #s merge the same way: a # placed so that it connects to two or more #s takes them into one # where it was placed, so # obstacles can be consolidated, moved and reduced (three #s become one).
- **Chain reaction.** After a merge, the placed tile's new value may match the tiles around it: three As make a B next to two other Bs. If its new value makes a group of 3 or more, it merges again, and keeps going as long as it can, so one move can make B, then C, then D. Every merge empties at least two tiles and fills none, so a chain always ends.
- **Rubble.** Merged-away tiles become empty, so without something pushing back a careful player could keep space free for ever. After the move (and any chain reaction), each merge of exactly 3 tiles leaves a # (rubble) on its cleared tile farthest from the placed one (`dropRubble`). Bigger merges leave none, so it pays to build bigger groups, and a merge of #s never leaves rubble, so cleaning up #s never makes more. Rubble comes from the player's move, so it merges like a placed #: rubble that lands touching two or more connected #s takes them into one # on its own tile (each rubble in turn, after the chain reaction). A rubble merge scores 1 per tile, with no chain bonus (see **Score**). The hover preview shows where the move's rubble would land and the #s it would merge, so rubble can be aimed at #s to tidy them up.
- **End.** The goal is to use up the board: the game ends when no empty tile is left (`outcome`), and the result is the score ("Board full. Score: 229 (highest tile D, 89 moves)."). Making a **Z** ends the game at once as a win, however many tiles are free ("You made Z, the top of the alphabet, in N moves. You win! Score: 900.").
- **Score.** Merges earn points, added up in the **Score** shown in the panel during play. A merge scores the **rung** it makes, the letter's place in the alphabet (`rungOf`: A 1, B 2, C 3 ... Z 26), times the tiles merged (`mergePoints`): three As make a B for 2 × 3 = 6, five Cs make a D for 4 × 5 = 20. Rungs climb in even steps, so the score grows steadily rather than threefold like the values. **Chain bonus:** each merge of a chain reaction scores times its place in the chain, the first ×1, the second ×2, the third ×3 (`scoreMerges`), so a move that makes a B from three As and then a C from three Bs scores 6 + 9 × 2 = 24. A merge of #s scores 1 per tile, so clearing obstacles is worth something; a rubble merge scores the same, with no chain bonus (`scoreRubble`). Wildcards need nothing extra: they make a higher rung, which scores more. Only merges score. Undo takes back a move's points with the move.
- **Top 10.** Each board size keeps its own top 10 (`TOP_SCORES`), since a bigger board allows bigger scores. Every board of a size has the same number of tiles (see Board: **Placement**), so scores on different random boards compare fairly. When a game ends, it is added to its size's list if it makes the top 10 (`addScore`): a higher score ranks higher, and on a tie the game that ended first stays ahead, so a tie with 10th place doesn't make it. An entry records the score, the highest tile, the moves, the date, and whether the game was won with a Z. Each game is recorded once, the first time it ends: Undo can reopen a finished game, but finishing it again doesn't add another entry. The lists are kept in this browser only.
- **Hot spare.** A second deal held in reserve, like the hold piece in Tetris: a value (or ★) and the shape it must go on. The spare starts each game empty. Tapping **Spare ⇄** with an empty spare keeps the next value (and its shape) as the spare, and a new next value is dealt. After that, tapping it swaps the next value with the spare, any number of times, at any point in the game (`swapSpare`). A swap isn't a move: it changes only the deal, not the board, the moves or the score. A spare coming into play takes the other shape if no empty tile of its own shape is left (`shapeInPlay`), so it can always be placed. A wildcard can be kept too, and saved for the right moment. The status line says what happened ("B kept as the spare.", "Swapped: B is next, A is the spare.").
- **Undo** is a power-up (the first from issue #33): it steps back one move, as far as the start of the game and including after the game ends, and each Undo spends a charge. A game starts with 3 charges (`UNDO_START`) and holds at most 5 (`UNDO_MAX`, `addUndos`). A move earns a charge for each rung its merges take the highest tile up (`undosEarned`): making a letter for the first time in the game (D, E, F ...) earns one, and a chain or big merge that climbs two rungs earns two. A value placed without a merge, a merge to a letter already made, and a merge of #s earn nothing. Undo takes back whatever the undone move earned, and the charge spent is not refunded (`undosAfterUndo`); the spare goes back to what it was before the move. The status line says when a charge is earned ("New letter D! +1 Undo.", or "Undos full (5)." at the cap) and how many are left after an Undo ("Move undone. 2 Undos left.").
- **Clear** is the second power-up from issue #33: it empties one tile of the player's choice, a letter or a #. A game starts with no Clear charges and holds at most 3 (`CLEAR_MAX`, `addClears`); a chain reaction, a move whose placed tile merges two or more times, earns one (`clearsEarned`; rubble merges don't count). Tapping **Clear (n)** arms it: the next tap on a letter or # empties that tile (`canClear`, `clearTile`) and spends a charge; a tap on an empty tile, tapping **Cancel Clear** or pressing Escape disarms it without spending. While armed, the merge preview is off and the tile under the pointer is outlined in red. Using Clear isn't a move: the deal, the moves and the score stay; the cleared tile gets the last-move outline. Undo takes back a Clear (giving the charge back, and spending an Undo charge as usual), and takes back a Clear earned by the undone move. The status line reports earning ("Chain! +1 Clear.", or "Clears full (3).") and using ("Cleared #. 0 Clears left.").
- **Suns and stars.** A sun is five kites meeting at their tips (a decagon); a star is five darts meeting at their tips (`findRosettes` in `src/lib/board.ts`). A medium board has about 5 suns and 2 stars, a small one about 2 and 1, a large one about 10 and 4. Each is marked by a small ring where the tips meet. Filling all five of its tiles, with letters or #s, completes it (`newlyCompleted`): the ring turns gold, and it earns **Any shape** charges, one for a sun and two for a star, the rarer (`ROSETTE_REWARD`, `anyShapesEarned`). Each counts once a game, so emptying one (by a merge or Clear) and filling it again earns nothing; one the starting seeds happen to fill earns nothing. The five tiles of a sun or star form a ring, each touching the next, so they can't all hold one letter without merging: completing one is about filling, not matching. The status line says "Sun! +1 Any shape." or "Star! +2 Any shape." (and "Any shapes full (3)." at the cap).
- **Any shape** is the third power-up from issue #33: the next value may go on an empty tile of either shape, ignoring the shape it was dealt. A game starts with none and holds at most 3 (`ANY_SHAPE_MAX`, `addAnyShapes`); suns and stars earn them. Tapping **Any shape (n)** arms it (the button turns amber and reads **Cancel Any shape**; the other shape's empty tiles are no longer shaded, and the preview works on either shape); placing the next value then spends it. Tapping the button again or pressing Escape disarms it without spending. Arming one power-up disarms the others. Undo takes back a move made with it, giving the charge back, and takes back charges and completions the undone move earned.
- **Upgrade** is the fourth power-up from issue #33: it raises one letter a rung (B to C), and the tile then merges as if that letter had just been placed there, with chain reactions, rubble and points (`upgradeAt`). A game starts with none and holds at most 3 (`UPGRADE_MAX`, `addUpgrades`); a big merge, a merge of 5 or more letters (`BIG_MERGE`; each one in a chain counts; merges of #s don't), earns one (`upgradesEarned`). Tapping **Upgrade (n)** arms it (the button turns green and reads **Cancel Upgrade**), and the next tap on a letter below Z upgrades it (`canUpgrade`; not a #, an empty tile or Z) and spends a charge; a tap elsewhere, the button again or Escape disarms it without spending. While armed, hovering a letter previews the upgrade: the new letter, the tiles its merges would clear and where rubble would land (`previewUpgradeAt`). Upgrading isn't a move: the deal and the move count stay; points and power-ups its merges earn count as usual. Arming one power-up disarms the others. Undo takes an Upgrade back, giving the charge back. The status line says "Big merge! +1 Upgrade." (or "Upgrades full (3).") and "Upgraded B to C."
- **Sweep** is the fifth power-up from issue #33: it clears every # on a tile and on the tiles touching it (`sweepTargets`, `sweepAt`). A game starts with none and holds at most 3 (`SWEEP_MAX`, `addSweeps`); each rubble merge (rubble that lands and merges #s) earns one (`sweepsEarned`). Tapping **Sweep (n)** arms it (the button turns slate and reads **Cancel Sweep**; the #s it would clear around the tile under the pointer are outlined in red), and the next tap on a tile with a # on or beside it sweeps them and spends a charge; a tap with no # there, the button again or Escape disarms it without spending. Sweeping isn't a move: the deal, the moves and the score stay; the tile tapped gets the last-move outline. Arming one power-up disarms the others. Undo takes a Sweep back, giving the charge back. The status line says "Rubble merge! +1 Sweep." (or "Sweeps full (3).") and "Swept 3 #s. 0 Sweeps left."
- **Swap** is the sixth power-up from issue #33: it exchanges what two tiles hold, and then each merges, with chain reactions, rubble and points, as if just placed there: first the tile picked first, then the other, unless the first merge emptied it (`swapAt`). Any two filled tiles holding different values can be swapped, letters or #s (`canSwap`), so a # can be moved out of the way. A game starts with none and holds at most 3 (`SWAP_MAX`, `addSwaps`); every 500 points scored earns one (`SWAP_SCORE_STEP`, `swapsEarned`). Tapping **Swap (n)** arms it (the button turns teal and reads **Cancel Swap**); the next tap picks the first tile (outlined in teal), and a tap on a tile holding something else swaps the two and spends a charge. While a first tile is picked, hovering a second previews the swap there (`previewSwapAt`). Tapping the first tile again unpicks it, a tap on another tile with the same value picks that one instead, and a tap on an empty tile, the button again or Escape disarms it without spending. Swapping isn't a move: the deal and the move count stay; points and power-ups its merges earn count as usual. Arming one power-up disarms the others. Undo takes a Swap back, giving the charge back. The status line says "500 points! +1 Swap." (or "Swaps full (3).") and "Swapped # and B."
- **New Game** starts over on a new board of the size picked from its menu.

## 5. Open questions

Each option below is implemented, and can be switched during play from the **How to play** dialog; a change applies at once, without restarting the game. The first one listed is the default.

Every question has a permanent number, Q1, Q2 and so on, given in the order the questions were opened. A number never changes and is never reused, so it means the same question here, in **Resolved questions** (section 8), in the game, and in pull requests and commits. The next new question is **Q17**.

### Q15. On a touch screen, what does a tap do?

A touch screen has no hover, so the merge preview (see Screen: **Hover**) is never seen before a move unless a tap can show it (`TapRule`, `tapAction`). A mouse always places with one click, whatever the option.

| Option | Behavior |
|---|---|
| Place at once (`place`) | A tap places the next value on the tile, as a click does |
| Preview, tap again to place (`preview`) | The first tap on an empty tile the next value can go on selects it and shows the preview there, as hovering does. A second tap on the same tile places. A tap on another such tile moves the selection there; a tap anywhere else (a filled tile, the wrong shape, off the board) clears it. A new game, Undo or a move clears it too; a swap with the spare keeps it, and the preview follows the new deal. The opening hint says to tap twice |

Still to think about: a move limit and a time limit; the next power-ups and other ways to earn them (#33); whether a swap with the spare should cost something.

## 6. Screen

Everything fits on one screen with no scrolling. The board is square, so the screen is split into a square for the board and a panel in the space left over:

- **Wide screens** (landscape): the board fills the height on the left, and the panel takes the rest of the width on the right, at least 16 rem wide (the board's square shrinks if needed to leave that).
- **Tall screens** (portrait): the board fills the width at the top, and the panel takes the rest of the height below, at least 12 rem tall.

Rotating a phone moves the panel between the side and the bottom; the game carries on.

| Element | Behavior |
|---|---|
| Next chip | The next value, at the top of the panel beside the title, drawn as a rounded tile with its letter, in the same colors that value has on the board (fill and number color, from `src/lib/colors.ts`, shared with the board drawing). A wildcard shows ★ on a rainbow gradient, a look no number has. The chip is cut into a kite or a dart, the shape the value was dealt, and outlined in the board's tile-edge gray, one pixel wide (`TILE_EDGE`), so a pale tile such as A stands out from the white panel. Each newly drawn value pops in (a quick grow and settle, 0.25 s), except when the device asks for reduced motion |
| Panel | From the top: the title and the Next chip; the stats as small cards (the score, moves, highest tile, free (empty) tiles); **Undo (n)**, showing the charges held (disabled with nothing to undo or no charges left), **Clear (n)** (disabled with no charges; red and reading **Cancel Clear** while armed), **Any shape (n)** (likewise; amber and reading **Cancel Any shape** while armed), **Upgrade (n)** (likewise; green and reading **Cancel Upgrade** while armed), **Sweep (n)** (likewise; slate and reading **Cancel Sweep** while armed), **Swap (n)** (likewise; teal and reading **Cancel Swap** while armed), **New Game ▾**, **Top 10** and **How to play**, wrapping onto more lines if the panel is narrow; then the status line |
| New Game menu | Small, Medium and Large, each with its tile count; the current board's size is highlighted. It opens below the button with the panel at the side, and above it with the panel at the bottom, so it stays on screen. Picking one starts a new game on a new random board of that size and remembers the size for next time. Escape or a click outside closes the menu without starting a game |
| Board | Scaled to fill its square (leaving 8 px around it) and centered. When the window changes size or the screen is rotated, the board is rescaled to fit. Empty tiles white with thin gray edges (one screen pixel wide at any scale), or light gray when they are the shape the next value wasn't dealt (not while Any shape is armed); a small white ring where each sun's or star's tips meet, gold once it is completed; #s a darker slate (`ZERO_FILL`) than those light gray tiles, so the two don't blur together; each letter, A to Z, in a color of its own (`RUNG_FILLS` in `src/lib/colors.ts`): A to J run through the light shades of the color wheel, pale yellow (A), yellow (B), orange (C), red (D), pink (E), purple (F), indigo (G), blue (H), teal (I), green (J); K to Y through deep shades in the same order and on into brown, wine, plum, navy, deep cyan, forest and slate (Y); and Z, the winning tile, is gold. The letter (or #) is near-black on the light shades, the # and Z, and white on the deep shades K to Y; every one has a contrast of at least 4.5 to 1. The letter sits on a kite at its centroid, on a dart along its axis toward the tip |
| Last move | Amber outline |
| Hover | The empty tile under the pointer is tinted blue and shows the value it would end up with: the value placed, or the result of its merges (including any chain reaction). The tiles those merges would clear get a blue outline. The tiles where the move's rubble would land show a gray # with a blue outline, and the #s that rubble would merge are outlined too. Occupied tiles show no preview. On a touch screen, with Q15's preview option, a first tap on a tile shows the same preview |
| Status line | Before the first move, a one-line hint on how to play (naming the dealt shape); then what a wildcard became ("Wild played as B.") the last move's merges and the points they scored ("Merged 3 tiles into B, then 3 tiles into C (+24).") any rubble dropped ("Rubble dropped a #.") and any rubble merges ("Rubble merged 3 #s into one (+3)."), or the result at the end of the game, with the score (see Rules: **End**) and, if the game made the top 10, its place ("#3 on the medium board!"). It wraps onto as many lines as it needs |
| Top 10 | A dialog over the board, opened by **Top 10** and opened by itself when a game ends. A button for each board size (Small, Medium, Large) switches between their lists, starting on the current board's size. Each row shows the place, score, highest tile (with 🏆 for a Z win), moves and date; the game that just ended, if it made the list, is highlighted. An empty list says no game on that board has finished yet. A note says the lists are kept in this browser |
| How to play | A dialog over the board: first the rules to try, one row of buttons per open question labeled with its number (now Q15), then how to play in a few short paragraphs |
| Spare | A **Spare ⇄** button beside the Next chip (on its own line when the panel is narrow), showing the spare as a chip like the Next chip (outlined the same way), or a dashed empty box. Tapping it keeps or swaps (see Rules: **Hot spare**); it is disabled when the game is over |
| Dialogs | Escape, the ×, **Done** or a click outside closes a dialog |

Pointer and touch both work: a click places on the tile under it, and a tap does too, or previews first (Q15).

## 7. Known limitations

- No sound, animation or skins yet (Penrogo's skin system could be brought over).
- No saved games. The top 10 lives in one browser only, with no names and no sharing between devices.
- Ideas not yet tried: how often wildcards should come up; letting the player choose what a wildcard becomes instead of it choosing the best; other special values.
- Not yet tested on a physical touch device (only in a browser emulating an iPhone). On touch screens there is no hover, so the merge preview is only seen with Q15's tap-to-preview.
- No offline play: the home-screen app needs the network to start.
